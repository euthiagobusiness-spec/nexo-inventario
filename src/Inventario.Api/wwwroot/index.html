ALGORITMO OBLIGATORIO

VentaService.RegistrarVenta

La API invoca el método académico dentro de una transacción MySQL: copia temporal de existencias, validación de detalles, cálculo de subtotales y actualización final. Se conservan los seis lazos while originales. Tres líneas usan decimal para el cálculo monetario.

RegistrarVenta(Venta venta, Producto[] productos)
Tiempo: O(n + m·n) · Memoria adicional: O(n)

n: productos cargados · m: detalles de la venta. La transacción y los bloqueos de filas coordinan ventas simultáneas; el algoritmo en memoria no sustituye esa protección.

El navegador usa la API del Backend. Solo el Backend debe conectarse a la base de datos. Una venta bloquea las filas de productos, verifica existencias y confirma todos sus cambios en una única transacción.

Recursividad demostrable

El valor del inventario se calcula dividiendo la lista en dos, sumando cada mitad y combinando los resultados. Caso base: lista vacía o un producto.

T(n) = 2T(n/2) + O(1)
Tiempo: O(n) · Pila: O(log n)

Alcance académico

Se usan referencias administradas por C#, sin punteros unsafe: no hay necesidad de acceso directo a memoria. La metodología, complejidad y límites están documentados en los archivos del proyecto. No incluye autenticación de usuarios, impuestos, devoluciones ni predicciones de demanda; su uso está limitado al laboratorio privado autorizado.
